# 早晚报同构与时区偏置设计

## 背景

当前仓库已经存在 `morning` 与 `evening` 两个 digest edition，但晚报仍带有过强的“来源硬分流”特征，且与早报在选题标准、去重视角与调度上还未完全对齐。

用户确认的新目标是：

- 早报与晚报在页面展示与内容组织上完全同构
- 区别主要来自时区造成的内容侧重，而不是机械的来源切分
- 早晚报之间必须去重，同一话题不能在两期中原样重复
- 早报改到北京时间 06:00 运行

## 设计目标

1. 早晚报都使用同一套内容规则：
   - `重点资讯` 必须是多源话题级叙事
   - `其他快讯` 可容纳高价值单源内容
   - `核心论文` 单独输出
   - 首页卡片摘要、条数统计、详情结构全部一致
2. 早报偏美国白天形成的话题，晚报偏东八区白天形成的话题
3. 允许跨区域重要内容进入另一版，但默认优先各自时区/实体侧重
4. 早晚报共享事件去重视图，follow-up 才允许二次入选

## 架构策略

### 1. 保留 edition 双轨

- `morning`：
  - 输出 `digest-YYYY-MM-DD.md`
  - 展示标签 `AI日报`
- `evening`：
  - 输出 `evening-digest-YYYY-MM-DD.md`
  - 展示标签 `AI晚报`

页面层不做分叉，继续复用现有首页、日报列表页与详情页模板。

### 2. 从“来源隔离”调整为“来源偏置”

来源不再理解为“仅属于某一期”，而是：

- `preferred_in: morning`
- `preferred_in: evening`
- `preferred_in: both`

运行某一期时：

- 所有 `both` 来源都参与
- 对应 `preferred_in` 的来源获得额外排序权重
- 非偏好来源仍可参与，但默认排位更低

这样可以兼顾：

- 早报偏海外
- 晚报偏国内
- 但不漏掉跨时区的大事件

### 3. 选题与深读偏置

除来源偏置外，再对 topic selection 施加 edition 偏置：

- `morning` 优先海外公司/模型/产品/监管动态
- `evening` 优先国内公司/模型/平台/产品/商业化/政策进展

晚报在 shortlist、ranking、deep-read 扩展三个阶段都应用国内实体优先。

### 4. 跨版去重

发布缓存不再只在 edition 内检查，而是：

- 默认检查所有 edition 已发布记录
- 同一事件签名若已被另一 edition 发布，则当前 edition 默认跳过
- 若存在 `newDevelopment` / `newSource` / 更新后的发布时间等 follow-up 信号，则允许再次入选

同一天重跑同一期仍允许复用原候选，避免本地走查时结果漂移。

## 内容规范

### 首页卡片

- 早报与晚报都展示 3 条以内主线摘要
- 条数统计都按 `重点资讯 + 其他快讯 + 核心论文` 真实总数计算
- 晚报仅在 badge 与标题文案上区别为 `AI 晚报 / AI晚报`

### 详情页

- 早晚报都使用同样的 section 结构与样式
- 早晚报都显示候选总数、主线、重点资讯、其他快讯、核心论文、参考来源

## 调度

- 早报 cron 从当前时间调整到北京时间 `06:00`
- 晚报保持晚间单独运行

## 验收标准

1. 早报和晚报页面结构完全同构
2. 晚报内容以国内话题为主，早报以海外话题为主
3. 早晚报之间无原样重复话题
4. 重大跨区域事件在另一版中仍可通过 follow-up 机制出现
5. GitHub Actions 中早报已改为北京时间 06:00
