# 早晚报统一增强设计文档

## 背景

当前仓库已经具备 `morning / evening` 双 edition 的 AI 日报能力，但还存在 3 个核心问题：

1. 国内来源池仍然偏窄，晚报候选量不足。
2. 重点资讯数量不稳定，存在不足 3 条的情况。
3. 排序虽然已有基础的 `pubDate / preferred_in / edition` 偏置，但还没有把“头部 AI 公司优先”和“时效性显式提升”做成硬规则。

本轮设计的目标是在不破坏现有业务功能的前提下，增强早报和晚报的选题质量与稳定性。

## 目标

1. 早报和晚报都统一执行：
   - `重点资讯` 至少 3 条
   - `其他快讯` 可继续承接高价值单源内容
   - `核心论文` 单独输出
2. 排序体系显式强化：
   - 头部 AI 公司 / 模型实体命中加权
   - 时效性权重提高
   - 可得热度信号作为加分项
3. 国内来源池扩充为三层结构：
   - 公开自动源
   - 官方 / 产品 / 开发者自动源
   - 微信 / 小红书等弱信号观察层
4. 早晚报保持完全同构，但通过 edition 偏置实现“美国白天 / 东八区白天”两种侧重。

## 非目标

1. 本轮不把微信公众号、小红书接成生产自动源。
2. 本轮不重做前端页面结构。
3. 本轮不引入新的外部付费数据服务。

## 方案总览

### 1. 排序增强

在现有 `scoreTopicForSelection` 体系上新增三类显式加权：

- 头部实体权重
  - 命中 OpenAI、Anthropic、Google/DeepMind、Meta、xAI、英伟达、MiniMax、智谱、阿里/通义/Qwen、字节/豆包/Seed、腾讯/混元、阶跃、Kimi/月之暗面、DeepSeek、百度/文心/千帆、华为/盘古、小米等实体时加分。
- 时效性权重
  - 在已有 `recencyBonus(pubDate)` 基础上提升占比。
  - 越接近当前 edition 的时间窗口，分数越高。
- 热度信号加分
  - 对能拿到阅读量、评论量、讨论度等信号的来源加分。
  - 拿不到时不扣分，只作为 bonus。

### 2. 重点资讯补齐

统一对早报和晚报执行：

- 正常先按现有多源话题叙事门槛筛 `重点资讯`
- 若 `重点资讯 < 3`
  - 从 `其他快讯` 候选中按综合分从高到低补齐
  - 仅允许高质量条目补齐，不能突破最低门槛

### 3. 来源扩充分层

#### 第一层：主自动源

直接进入 `sources.yml` 自动抓取链路，优先覆盖：

- `ai-bot.cn/daily-ai-news/`
- `AIBase`
- `36Kr AI`
- `AITNT 资讯`
- `量子位`
- `雷锋网 AI`
- `机器之心`

#### 第二层：官方 / 产品 / 开发者自动源

用于提升头部公司一手信号：

- MiniMax
- Kimi / 月之暗面
- 智谱
- DeepSeek
- Qwen / 通义 / 阿里云 Model Studio
- 火山引擎 / Seed / 豆包
- 腾讯混元
- 百度千帆 / 文心
- 华为盘古

#### 第三层：弱信号观察层

本轮只保留设计，不接入生产自动链路：

- 微信公众号（例如量子位公众号）
- 小红书账号（例如秋芝 2046）
- 论坛 / 社区 / 个人信息流

这些来源只能用于标题发现、弱信号观察或半自动补录。

### 4. edition 偏置

不按来源做死切分，而是用共享来源池 + edition 偏置：

- 早报
  - 侧重美国白天形成的海外 / 国际动态
- 晚报
  - 侧重东八区白天形成的国内动态

两者继续共享跨 edition 去重逻辑。

### 5. 时间与发布行为

- 早报默认发布时间：`06:00:00`
- 晚报默认发布时间：`19:40:00`
- 同日手动运行时：
  - 若当前时间早于配置发布时间，front matter 使用当前本地时间
  - 不允许出现未来时间

## 风险

1. 国内资讯站之间重复率高，必须依赖去重和 topic clustering。
2. 官方源更新慢，单靠官方源不足以撑起晚报广度。
3. 机器之心、部分 JS-heavy 官网可能抓取不稳定，只能作为补充源。
4. 微信 / 小红书自动化风险高，不应进入主链路。

## 验收标准

1. 早报和晚报都至少有 3 条 `重点资讯`
2. `重点资讯` 中头部 AI 公司 / 模型动态占比明显提升
3. 晚报候选池规模较现状抬升
4. 时效性更高的内容在排序中更易上浮
5. 微信 / 小红书不进入生产自动源
6. `npm run test:digest`、`npm run clean && npm run build` 通过
7. 本地页面访问正常：
   - 首页
   - 日报列表
   - 早报详情
   - 晚报详情
